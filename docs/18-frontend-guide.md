# 18. Веб-интерфейс GeoAssist

## Запуск готового проекта

Из корня `GeoAssist`:

```powershell
docker compose up --build -d
docker compose ps
```

Сайт: **http://localhost:8080**. Отдельный Node.js для этого запуска не нужен. На первом старте MongoDB получает демоданные Астаны; повторные запуски сохраняют пользовательские изменения. `docker compose down` останавливает стенд с сохранением volume.

|---|---|---|
| Пользователь | student01@geoassist.local | Student-demo-2026! |
| Администратор | admin@geoassist.local | Admin-demo-2026! |

Порты привязаны к этому компьютеру. Для MongoDB Compass используйте `mongodb://localhost:27018/?replicaSet=rs0&directConnection=true`.

## Что где находится

| Страница | Что можно сделать |
|---|---|
| `/explore` | Поиск по началу названия, категории, тегам; геопоиск; список и карта; страницы по 20 мест |
| `/places/:id` | Карточка и координаты; избранное; оценка; явный выбор места; переход в историю |
| `/register`, `/login` | Регистрация обычного пользователя и вход; регистрация не создаёт сессию |
| `/profile` | Изменение имени и любимых категорий, включая очистку всех категорий |
| `/favorites` | Избранные места и удаление из списка |
| `/history` | Просмотры, выбор, добавление/удаление избранного и оценки; фильтры по месту/типу |
| `/admin/places` | Поиск в каталоге, добавление, редактирование и удаление места |
| `/admin/places/new`, `/admin/places/:id/edit` | Одна форма для создания и редактирования, выбор точки на карте |

История появляется только после входа. Открытие карточки сохраняет `view` один раз за посещение; повторная загрузка данных в том же посещении не создаёт дубль. «Выбрать это место» сохраняет `select`; это запись интереса, а не бронирование или построение маршрута. При потерянном ответе повтор события использует тот же UUID. Избранное и оценки создают свои события на backend.

Удаление места логическое: оно исчезает из каталога и избранного, но остаётся в истории как «Место недоступно». Из такой строки можно убрать сохранившееся избранное/оценку. Новые действия для удалённого места запрещены.

Все 19 бизнес-маршрутов API используются интерфейсом. Health-check остаётся служебным endpoint. Рекомендации, запросы на естественном языке и интеграция с мессенджером пока не реализованы.

## Архитектура в коде

```text
web/src/
  main.tsx                        # QueryClient, BrowserRouter, SessionProvider
  app/
    App.tsx                       # маршруты, защищённые страницы, меню, выход
    session.tsx                   # /me, смена аккаунта, синхронизация вкладок
    query-client.ts               # политика GET retry и свежести данных
    styles.css                    # стили, адаптация под телефон, фокус клавиатуры
  pages/                          # восемь экранов; Auth объединяет вход/регистрацию
  modules/
    identity/                     # API и проверки профиля/пароля
    catalog/                      # API, фильтры URL, формы мест, PlaceCard
    activity/                     # избранное/оценки/история, дедупликация событий
  shared/
    api/client.ts                 # fetch, cookie, CSRF, ошибки, отмена старых запросов
    api/generated/schema.d.ts     # типы, сгенерированные из OpenAPI
    api/types.ts                  # короткие имена DTO
    lib/                          # форматирование, координаты, общие проверки
    map/MapCanvas.tsx             # Leaflet, маркеры, радиус, выбор точки
    ui/                           # поля, ошибки, пустой экран, пагинация, диалог
```

Страница собирает несколько модулей; модуль обращается к API через единый клиент. Модули не зависят друг от друга. Для небольшого текущего интерфейса роуты/guards собраны в `App.tsx`, стили — в одном `styles.css`: пустых папок и отдельного слоя репозиториев на frontend нет. Серверное состояние хранит TanStack Query, формы — React Hook Form + Zod, фильтры каталога — URL.

Авторизация использует HttpOnly cookie. JWT/localStorage для токенов нет. API-клиент добавляет `X-GeoAssist-CSRF: 1` к изменяющим запросам, браузер добавляет Origin. При смене пользователя отменяются незавершённые запросы и удаляется личный кэш; BroadcastChannel обновляет сессию в соседних вкладках. Роль в UI не заменяет серверную проверку.

В `PlaceEditor` хранится исходная версия места. PATCH отправляет изменённые поля и `expected_version`; DELETE — версию в query. При 409 интерфейс показывает актуальную запись и сохраняет черновик, чтобы пользователь явно выбрал дальнейшее действие. POST создания автоматически не повторяется.

## Карта и геопоиск

Координаты API — `{longitude, latitude}`, Leaflet получает `[latitude, longitude]`. Центр по умолчанию: Астана, `71.4304, 51.1282`. Радиус 1–50000 м; расстояние по прямой. Теги в URL повторяются (`tag=wifi&tag=quiet`) и объединяются условием AND. Запрос `q` ищет начало полного названия.

Страница карты содержит только текущую порцию мест; общего количества API не возвращает. Ссылка сохраняет фильтры и смещение. При недоступной геолокации можно выбрать центр Астаны, ввести координаты или кликнуть по карте. При недоступных тайлах остаются данные и формы. Подложка — OpenStreetMap с атрибуцией; для большого публичного сервиса понадобится подходящий tile provider.

Провайдер можно заменить через `VITE_MAP_TILE_URL` и `VITE_MAP_ATTRIBUTION` перед `npm run build`. Это параметры сборки, а не runtime-переменные контейнера. Dockerfile принимает одноимённые build args (`docker compose build --build-arg VITE_MAP_TILE_URL=... --build-arg VITE_MAP_ATTRIBUTION=... api`). В стандартной сборке используются значения по умолчанию.

## Разработка и проверки

Режим Vite с live reload описан в [README](../README.md). Node закреплён в `.node-version`, точные зависимости и транзитивные версии — в `package-lock.json`. TypeScript 5.9.3 выбран по совместимости генератора OpenAPI и eslint. Обновлять зависимости следует вместе с lockfile и проверками.

Из `web`:

```powershell
npm ci
npm run api:generate
npm run typecheck
npm run lint
npm run test
npm run build
```

Не редактируйте `generated/schema.d.ts` вручную. Для форматирования: `npx prettier --write src e2e`; генерируемые файлы исключены. В package.json закреплён override `minimatch@>=7 <11.0.1 → 11.0.1` для зависимостей инструментов разработки: он устраняет найденное audit-замечание, а совместимость проверена запуском lint/генератора/сборки. Не удаляйте override без обновления зависимостей и повторной проверки.

Браузерные тесты работают **только на отдельном стенде**:

```powershell
# Из корня; Docker Compose 2.24.4+ нужен для !override портов.
docker compose -p geoassist-e2e -f compose.yaml -f compose.e2e.yaml up --build -d --wait
cd web
npx playwright install chromium
npm run test:e2e
cd ..
docker compose -p geoassist-e2e -f compose.yaml -f compose.e2e.yaml down
```

E2E использует сайт `localhost:8081`, MongoDB `localhost:27019`, базу `geoassist_e2e` и volume `geoassist-e2e_mongo_data`. Cookie на localhost не разделяются по портам, поэтому E2E запускается в изолированном браузерном контексте Playwright. Тесты не используют открытый браузер пользователя. Регистрационный тест создаёт уникальный аккаунт; место после проверки логически удаляется. Ограничения частоты запросов не отключаются: многократные повторные запуски подряд могут получить 429.

Unit-тесты проверяют фильтры, координаты, UTF-8 длину пароля, безопасный return URL, 204/ошибки API и дедупликацию событий. E2E проверяет реальные API, cookies, профиль, избранное/оценки, историю, CRUD и конфликты. Сетевые сбои моделируются только в отдельных шагах теста. Внешние тайлы и шрифты в автоматических сценариях отключены, чтобы проверка бизнес-логики не зависела от интернета.

Статический adapter Go проверяется отдельно: прямые ссылки получают SPA, неизвестные `/api/*`, `/health/*`, assets и скрытые файлы не превращаются в HTML. Интеграционные тесты backend используют временные базы `geoassist_test_*`; команды есть в README.

## Если что-то не работает

- 403 при отправке формы: адрес браузера должен совпадать с `APP_ORIGIN`; после его изменения пересоздайте контейнер `api`. В Docker используйте `localhost:8080`, в Vite — `localhost:5173`.
- Пустая подложка: проверьте доступ к OpenStreetMap; сам каталог не зависит от загрузки тайлов.
- После изменения исходников сайт старый: выполните `docker compose up --build -d`; обычный restart не пересобирает образ.
- 409 при редактировании: перечитайте запись и выберите актуальные данные либо свой черновик. Не подставляйте случайную версию.
- Пароль: 12–72 **байта UTF-8**; кириллица может занимать больше одного байта на символ.
