# 14. Экраны и пользовательские сценарии

> Обновление 12.11.2026: frontend реализован. Этот документ сохраняет исходный план; фактическая структура и команды описаны в [руководстве 18](18-frontend-guide.md). Результаты проверок — [документ 19](19-frontend-verification.md).

Статус: план. [Обзор](12-frontend-plan.md) · [API](15-frontend-api-state.md).

## Навигация и доступ

| URL frontend | Экран | Кто видит |
|---|---|---|
| `/` | Перенаправление на `/explore` | Все |
| `/explore` | Поиск, список и карта | Все |
| `/places/:id` | Карточка места | Все; личные действия после входа |
| `/login` | Вход | Гость |
| `/register` | Регистрация | Гость |
| `/profile` | Профиль | User/admin |
| `/favorites` | Избранное | User/admin |
| `/history` | История | User/admin |
| `/admin/places` | Управление каталогом | Admin |
| `/admin/places/new` | Создание места | Admin |
| `/admin/places/:id/edit` | Редактирование места | Admin |
| Остальные пути | Страница не найдена | Все |

Общая шапка: GeoAssist, «Места», после входа «Избранное», «История», меню профиля и «Выйти». У admin появляется «Управление местами». Admin сохраняет все возможности обычного пользователя. Отдельной страницы входа администратора нет.

До завершения `GET /me` защищённые страницы показывают загрузку, а не мигающую форму входа. Для гостя сохраняем безопасный внутренний `returnTo`. После входа возвращаем его на нужную страницу; действие пользователь нажимает повторно. Чужие домены и URL вида `//host` в returnTo запрещены.

## Каталог и карта

На компьютере — фильтры, список карточек и карта рядом. На телефоне — переключатель «Список / Карта», фильтры раскрываются отдельной панелью. Карта не должна занимать экран так, чтобы пропадали результаты и действия.

Фильтры: начало названия, одна категория, несколько тегов, переключатель «Искать рядом», центр и радиус. Кнопки «Найти» и «Сбросить». Предпочтительные категории профиля не включают фильтры автоматически.

В карточке списка: название, категория, адрес, теги и расстояние, если оно пришло из геопоиска. Вместо отсутствующих фотографий — спокойное обозначение категории. Нет вымышленных фотографий, среднего рейтинга или «популярности»: этих полей API не отдаёт.

Кнопка «Подробнее» открывает карточку. Личные переключатели размещаем в карточке места, а не на каждом результате: текущий поиск не возвращает личное состояние, и нам не нужен отдельный state-запрос на каждую строку.

Пагинация — «Назад / Далее». Показываем число загруженных результатов, но не выдумываем общее количество. Фильтры и номер порции сохраняются при возврате из карточки. Детали карты — [документ 16](16-frontend-map-search.md).

## Карточка места

Название, описание, категория, адрес, теги, точка на карте, координаты в раскрываемом блоке. Расстояние показываем только при известном контексте поиска; `GET /places/:id` сам расстояние не вычисляет.

После входа доступны:

- «В избранное» / «Убрать из избранного»;
- «Моя оценка» от 1 до 5 и «Убрать оценку»; отсутствие оценки отличается от 0;
- «Выбрать это место» — явная фиксация события `select`, подтверждаем сообщением «Выбор сохранён в истории»;
- переход к истории именно этого места.

Выбор не является бронью, сохранённым маршрутом или вторым избранным. API хранит событие, поэтому не показываем постоянный переключатель «выбрано».

При открытии успешно загруженной активной карточки вошедшим пользователем записываем `view` по правилам документа 15. Просмотр списка, наведение на маркер и открытие admin-редактора просмотрами не считаются.

Гость видит приглашение войти рядом с личными действиями. При 404 — «Место недоступно», переход в каталог; при сбое сервера — возможность повторить загрузку, а не сообщение об удалении.

## Регистрация и вход

Регистрация: email, пароль, имя, необязательные любимые категории из справочника. Подсказка о длине пароля отображается до отправки. После 201 показываем «Аккаунт создан, войдите», открываем login с заполненным email, без сохранения пароля в URL или хранилищах. Регистрация сама сессию не создаёт.

Вход: email/пароль, показ/скрытие пароля, состояние отправки. Ошибка неверных данных — рядом с формой. При ограничении частоты показываем время ожидания из `Retry-After`; не пытаемся входить автоматически по таймеру.

Не вводим экран смены пароля или email: текущий API таких операций не поддерживает. Демоаккаунты остаются в README, не делаем жёстко заданный автовход из интерфейса.

## Профиль

Email только для чтения, редактируемые имя и любимые категории. Кнопка сохранения активна при изменениях и корректной форме. Удалить все предпочтения можно через пустой массив. После успеха новое имя появляется в шапке. Роль пользователь не редактирует.

## Избранное

Список активных любимых мест с датой добавления и своей оценкой, пагинация, переход в карточку, удаление из избранного. Нет фильтров по категории/радиусу: endpoint избранного их не поддерживает. Изменять оценку можно в карточке.

При удалении последней строки порции перечитываем список и при необходимости возвращаемся на предыдущую порцию. Пустой список предлагает перейти к поиску. Удалённые администратором места сервер не возвращает в избранном.

## История

События по времени, русские названия типов, дата и время, место, старое/новое значение оценки при наличии. Фильтры: тип события и конкретное место. Место выбирается через поиск названия или переход из карточки; обычный пользователь не должен вводить ObjectID вручную.

Типы: просмотр, выбор, добавление/удаление избранного, установка/удаление оценки. События удаления мест не придумываем: их нет среди типов interactions.

API истории отдаёт `place_id`, а не название. На странице подгружаем уникальные места текущей порции через общий кэш, не более четырёх таких запросов одновременно. Для удалённого места: «Место недоступно», история остаётся видимой. При сетевом сбое: «Не удалось загрузить название», повтор отдельно. Обновление страницы истории само не создаёт view-события.

Для удалённого места из истории можно открыть состояние через `/me/places/:id/state` и убрать оставшееся избранное/оценку. Добавлять или ставить новую оценку недоступному месту нельзя. Это сохраняет существующие возможности API без отдельного экрана удалённых мест.

## Управление местами

Список каталога с поиском и пагинацией, кнопка создания, действия «Редактировать» и «Удалить». На узком экране таблица превращается в карточки.

Общая форма create/edit: название, описание, категория, теги, адрес, широта и долгота. Точку можно поставить на карте или заполнить численно. Адрес вводится вручную: геокодера в backend нет.

При редактировании сохраняем исходную `version`; PATCH передаёт её как `expected_version` и только изменённые поля. Версия — служебное значение формы, не поле для ручного ввода. При 409 не затираем введённый текст: показываем свежие значения и предлагаем заново применить изменения. Автоматического повторения с новой версией нет.

Удаление требует диалога с названием места. После 204 обновляем каталог и связанные кэши. При 404 объясняем, что место уже недоступно; при 409 перечитываем запись и просим заново подтвердить удаление. Восстановление удалённого места не предлагаем — API этого не умеет.

## Общие состояния и оформление

Светлый интерфейс, один основной акцент, читаемые карточки и кнопки. Подпись «Демонстрационные места Астаны» объясняет происхождение данных. Единый набор компонентов для полей, сообщений, загрузки и подтверждений; анимации вторичны.

Каждый экран имеет состояния loading/error/empty/success. Повторное нажатие во время сохранения блокируется. У форм сохраняется введённый текст при ошибке. У ошибок есть понятное сообщение; технический request ID можно раскрыть для диагностики.

Поля имеют labels, ошибки связаны с ними, клавиатурный фокус виден. Диалоги удерживают фокус и возвращают его на исходную кнопку. Оценка доступна клавиатурой. Цвет не является единственным индикатором. Все действия доступны через список и формы без использования карты.
