# Проверка GeoAssist через Postman

1. Запустите проект по инструкции в корневом README и дождитесь готовности API.
2. В Postman выберите Import и импортируйте `GeoAssist.postman_collection.json` и `GeoAssist.local.postman_environment.json`.
3. Выберите окружение `GeoAssist local (demo credentials)`.
4. Запустите коллекцию по порядку через Collection Runner, одна итерация. Cookie jar должен быть включён.

Коллекция содержит 34 запроса: проверка готовности, категории, геопоиск по Астане, регистрация, вход, профиль, создание и изменение места администратором, избранное, оценки, события, история, удаление и выход.

Каждый запрос проверяет ожидаемый HTTP-статус. Идентификатор и версия созданного места сохраняются автоматически. Повтор события просмотра использует тот же event_key и ожидает 200 вместо 201. Последний GET удалённого места намеренно ожидает 404 — это успешная проверка логического удаления.

Для изменяющих запросов скрипт коллекции автоматически добавляет `Origin` из окружения и `X-GeoAssist-CSRF: 1`. Postman сохраняет сессионную cookie после входа; токен не требуется копировать вручную.

## Демонстрационные аккаунты

| Роль | Email | Пароль |
|---|---|---|
| Администратор | admin@geoassist.local | Admin-demo-2026! |
| Пользователь | student01@geoassist.local | Student-demo-2026! |

Это публичные синтетические аккаунты локального стенда. Они не подходят для опубликованного приложения. Реальные пароли и сессионные cookies в экспорт коллекции не добавляйте.

## Повторный запуск

Каждый прогон создаёт нового пользователя с уникальным email и одно место, которое в конце логически удаляется. Пользователь и история сохраняются в базе. Если остановить прогон раньше, созданное место может остаться активным; продолжите с нужного шага, чтобы завершить очистку.

Между полными прогонами выдерживайте минуту: действуют лимиты входа. Регистрация ограничена пятью запросами в час с одного IP. При 429 ориентируйтесь на `Retry-After`, не отключайте проверки для демонстрации.

Если изменён адрес API, обновите `base_url` и `origin`. Значение origin должно точно совпадать с `APP_ORIGIN` сервера. Для запуска отдельных запросов сначала выполните соответствующий вход, а для операций с `{{place_id}}` — создание места.
