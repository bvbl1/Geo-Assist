Assignment 6 уже сдан. Этот план был подготовлен перед созданием браузерного интерфейса для существующего Go API. По нему реализованы frontend, команды запуска и раздача статики; ниже сохранены проектные решения.

## Как будет выглядеть результат

Пользователь открывает GeoAssist, ищет места Астаны в списке и на карте, читает карточку, входит в аккаунт, добавляет места в избранное, ставит оценки и просматривает историю. Администратор через тот же сайт создаёт, редактирует и удаляет места. Для этих действий Postman больше не нужен.

Интерфейс на русском, адаптируется к компьютеру и телефону. Это адаптивный сайт, а не отдельное мобильное приложение. Данные берём из существующей MongoDB через API; браузер к базе напрямую не подключается.

## Выбор технологий

| Технология | Для чего она нужна в нашем проекте |
|---|---|
| React + TypeScript | Экраны и повторно используемые элементы; типы помогают находить ошибки в данных до запуска |
| Vite | Быстрый запуск разработки и сборка HTML/CSS/JavaScript |
| React Router, declarative mode | Адреса страниц, переходы, возврат назад и прямые ссылки |
| TanStack Query | Загрузка API-данных, кэш и обновление экранов после действий |
| React Hook Form + Zod | Формы и проверка ввода до отправки на сервер |
| CSS Modules + общие CSS-переменные | Изолированные стили компонентов и единые цвета, размеры, отступы |
| Leaflet + React Leaflet | Карта, маркеры, круг поиска и выбор координат |
| Стандартный `fetch` | HTTP-запросы через один общий клиент |
| openapi-typescript | Генерация TypeScript-типов из нашего `api/openapi.yaml` |
| Vitest + Playwright | Проверки сложных преобразований и основных сценариев в браузере |

Node.js нужен для разработки и сборки. В готовом Docker-стенде отдельный Node-сервер не нужен: Go раздаёт собранный frontend и обслуживает API. MongoDB остаётся в Docker с существующим volume.

Точные совместимые версии библиотек фиксируем при реализации в `package.json`, `package-lock.json` и версии Node для локального окружения/Docker. Установка в повторных сборках — `npm ci`. Сейчас не добавляем зависимости только ради плана.

### Почему такой выбор

У нас уже есть самостоятельный Go backend, а главные задачи интерфейса — карта, формы, фильтры и личные данные. Поэтому предлагается SPA: браузер получает приложение и обращается к существующему REST API. Серверный рендеринг для текущей учебной версии не является требованием. React описывает Vite как один из вариантов такой сборки, одновременно предупреждая, что маршрутизацию и работу с данными потребуется организовать отдельно — здесь это решают Router и Query. [Документация React](https://react.dev/learn/build-a-react-app-from-scratch).

Go templates + HTMX также возможны, но синхронизацию карты, фильтров и локального состояния всё равно пришлось бы писать на JavaScript. Выбираем один подход с React. Next.js добавил бы возможности серверного frontend-фреймворка, которые сейчас не нужны рядом с готовым Go API. Redux/Zustand пока не добавляем: серверные данные живут в Query, фильтры — в URL, состояние формы — в форме.

Старые `web/templates` и `web/static` в документе 01 были предварительным вариантом. Для нового этапа их заменяет план `web/src` → `web/dist`; Go backend сохраняет модульный монолит и Clean Architecture.

## Что входит в первый frontend

| Область | Возможности |
|---|---|
| Каталог | Категории, поиск по началу названия, теги, пагинация, карточка места |
| Геопоиск | Центр и радиус, местоположение браузера по запросу, выбор точки вручную, карта и список |
| Аккаунт | Регистрация, вход, выход, просмотр и изменение профиля |
| Предпочтения | Добавить/убрать избранное, поставить/изменить/убрать оценку |
| События | Просмотр карточки, явный выбор места, история и её фильтры |
| Администрирование | Список мест, создание, изменение, логическое удаление, обработка конфликта версии |
| Устойчивость | Пустые результаты, ошибки API, истёкшая сессия, недоступная карта, узкий экран |

Охватываем все 19 бизнес-маршрутов существующего API. Миграции, seed и создание администраторов остаются серверными командами, а health endpoints — техническими проверками.

В этом этапе не добавляем рекомендации, обработку естественного языка, мессенджер, отзывы текстом, фотографии, бронирования, маршруты по дорогам, управление чужими аккаунтами или восстановление пароля: соответствующих API сейчас нет. Для рекомендаций сохраняем точку расширения, но не показываем вымышленные персональные подборки.
