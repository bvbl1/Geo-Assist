# 17. Этапы реализации и критерии готовности

> Обновление 12.11.2026: frontend реализован. Этот документ сохраняет исходный план; фактическая структура и команды описаны в [руководстве 18](18-frontend-guide.md). Результаты проверок — [документ 19](19-frontend-verification.md).

Статус: план. Документация создана до разработки frontend. [Общий план](12-frontend-plan.md).

## Последовательность

| Этап | Что делаем | Проверяемый результат |
|---|---|---|
| 1. Каркас | Vite/React/TypeScript, Router, Query, CSS, общий API-клиент, типы из OpenAPI, dev proxy | Страница открывается, категории приходят из настоящего API, ошибка сети видна |
| 2. Сессия | Login/register/logout, `/me`, защищённые страницы, роли, CSRF, профиль | Вход сохраняется после обновления страницы; данные разных аккаунтов не смешиваются |
| 3. Каталог | Список, фильтры, URL, пагинация, карточка, справочник | Поиск по названию/категории/тегам работает без Postman |
| 4. Геопоиск | Карта, выбор центра, радиус, геолокация, fallback | Список и карта показывают одну порцию; отказ геолокации не ломает поиск |
| 5. Личные действия | State, избранное, оценки, view/select, история | Все действия сохраняются в MongoDB, нет лишних дублей событий |
| 6. Администратор | Список, create/edit/delete, конфликты версий | CRUD проходит через UI; обычный пользователь не может изменять каталог |
| 7. Сборка | Go static adapter, Docker stage, `WEB_DIR`, SPA fallback | `docker compose up --build -d` запускает сайт вместе с API и базой |
| 8. Приёмка | Браузерные сценарии, мобильный экран, ошибки, документация запуска | Получается воспроизводимая версия для демонстрации и развития на Final Project |

Карту делаем после работающего поиска в списке, чтобы ошибки внешней подложки не скрывали проблемы API. Каждая стадия использует живой backend; заглушки допустимы только внутри изолированных тестов.

## Что потребуется изменить в backend и инфраструктуре

Бизнес-API уже достаточно для первого интерфейса. Новая база, JWT, CORS для произвольных origins и отдельный frontend backend не требуются.

Планируемые технические изменения:

- `internal/platform/config`: необязательный `WEB_DIR`, проверка пути;
- `internal/platform/webui`: static files и ограниченный SPA fallback;
- `internal/bootstrap`: подключение adapter без изменения API 404/405;
- `deploy/Dockerfile`: Node build stage и копирование dist в Go runtime;
- `compose.yaml`: `WEB_DIR` для API, существующий volume/seed сохраняются;
- `.gitignore`, `.dockerignore`: `web/node_modules`, локальный `web/dist`, результаты frontend-тестов;
- `.env.example` и README: два режима APP_ORIGIN, команды frontend и Postman;
- OpenAPI: уточнение обнаруженных расхождений описания и реализации, без скрытого изменения бизнес-контракта.

Если позже потребуется выдача состояния для множества мест или название места прямо в истории, это отдельное обоснованное расширение API. Первый frontend умеет работать без него.

## Планируемые команды

Команды ниже реализованы. Изолированный E2E-стенд и порядок запуска описаны в [руководстве 18](18-frontend-guide.md).

```powershell
# Frontend-разработка: backend уже работает с APP_ORIGIN=http://localhost:5173
cd web
npm ci
npm run dev

# Проверки и сборка frontend
npm run api:generate
npm run typecheck
npm run lint
npm run test
npm run build
npm run test:e2e
```

`api:generate` читает `../api/openapi.yaml`. Генерируемый файл коммитим и проверяем, что регенерация не даёт неожиданных изменений. Зависимости и версия Node закреплены в репозитории; инструкция будет содержать конкретную версию, выбранную по совместимости библиотек.

Для готового Docker-стенда из корня остаётся `docker compose up --build -d` с `APP_ORIGIN=http://localhost:8080`; сайт доступен на 8080, MongoDB — на 27018. Первый старт импортирует тестовые данные, последующие сохраняют уже внесённые изменения. Во время разработки не используем `down -v` для «обновления» frontend.

## Что проверять тестами

Тестируем поведение, где вероятна ошибка, а не каждую строку JSX.

**Vitest:** преобразование координат, сериализация тегов и полного geo-набора, валидация URL/чисел/UTF-8 длины пароля, обработка 204 и JSON-ошибок, dedup/retry событий, очистка кэша при смене пользователя. [Документация Vitest](https://vitest.dev/guide/).

**Playwright:** основные пути в настоящем браузере с Go API и MongoDB, включая cookie, Origin, прямые ссылки и обновление страниц. [Документация Playwright](https://playwright.dev/docs/intro).

Для E2E создаём отдельный Compose project/volume/database с отдельными портами. Не используем рабочую `geoassist` и не удаляем пользовательские данные. Учётные записи создаём через seed, уникальный register-тест выполняем ограниченное число раз: действующие лимиты регистрации/входа не отключаем для удобства тестов. Изоляция cookie-контекстов браузера не отменяет IP rate limit.

Сетевые ошибки и отказ геолокации моделируем в браузерных тестах. Проверки не зависят от доступности внешних тайлов: подложку можно подменить тестовым ответом, а реальные места/радиус всё равно берутся из API. Отдельно вручную проверяем рабочую OSM-карту и атрибуцию.

После изменения Go router/static adapter запускаем текущие Go-тесты, включая интеграционные проверки на отдельной тестовой базе. Документируем фактически выполненные проверки, не переносим старые результаты в новый релиз как новые.

## Приёмочные сценарии

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Гость открывает каталог и карточку | Данные из API, личные действия предлагают вход |
| 2 | Название + категория + несколько тегов | AND-фильтрация; Back восстанавливает фильтры и порцию |
| 3 | Геопоиск вокруг центра Астаны | distance_m, радиус и координаты корректны, оси не перепутаны |
| 4 | Отказ в геолокации / нет тайлов | Работают список и ручной выбор координат |
| 5 | Регистрация с коротким/кириллическим паролем | Проверяется именно UTF-8 длина, есть подсказка |
| 6 | Регистрация и последующий вход | Нет ложного автовхода; cookie сохраняет сессию |
| 7 | Изменение профиля и очистка категорий | Шапка обновляется, `[]` действительно очищает |
| 8 | Избранное и оценка 5 → 4 → убрать | UI соответствует State; история отражает изменения |
| 9 | Повторное favorite или та же оценка | Нет лишнего события; запросы одного места не гоняются |
| 10 | Открыть карточку, refetch, выбрать место | Один view за посещение; select только по кнопке |
| 11 | Повтор отправки события после потери ответа | Сохраняется UUID, backend возвращает replay, не дубль |
| 12 | Фильтры и пагинация истории | Все шесть типов доступны; выбранное место фильтрует список |
| 13 | Admin создаёт и меняет место | Новая карточка и актуальная версия появляются в каталоге |
| 14 | Две вкладки редактируют одну версию | Второе сохранение показывает 409, черновик не теряется |
| 15 | Admin удаляет место | Оно исчезает из каталога/избранного, история остаётся |
| 16 | Очистка state удалённого места из истории | Удаление оценки/favorite работает, добавление заблокировано |
| 17 | Выход, вход другим аккаунтом, истечение сессии | Старые личные данные и поздние ответы не появляются |
| 18 | Обычный user открывает admin URL | UI объясняет запрет; API независимо отклоняет запись |
| 19 | Refresh прямой ссылки; неизвестный API/asset | SPA открывается; API/asset не маскируются HTML-ответом |
| 20 | 403 CSRF, 429, 503, потерянный ответ mutation | Понятные сообщения, без ложного успеха/слепого повторного create |
| 21 | Телефон и клавиатура | Формы, диалоги, рейтинг, пагинация и действия доступны |
| 22 | Перезапуск Docker | Пользовательские изменения и seed-маркер сохранены |

## Definition of done

Первый frontend готов, когда все 19 бизнес-маршрутов доступны через осмысленные сценарии, пройдены соответствующие приёмочные проверки, нет мок-данных в рабочем приложении, и проект запускается по обновлённому README. Карта не является обязательной зависимостью для регистрации/CRUD/избранного. Typecheck, lint, build и выбранные тесты проходят; ограничения и оставшиеся проблемы записаны явно.

К этому моменту пользователь может демонстрировать текущий функционал без Postman. Рекомендательная система, NL-запросы и мессенджер остаются следующими этапами и не заявляются как готовые.
