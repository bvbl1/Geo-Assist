## Начальный экран

Центр карты — демонстрационная область Астаны: `longitude=71.4304`, `latitude=51.1282`. Это центр тестовых данных, а не определённое местоположение пользователя.

Первое открытие `/explore` показывает обычный каталог без ограничения радиуса, `limit=20`, `offset=0`. Карта показывает ту же порцию результатов. Пользователь включает «Искать рядом», выбирает точку и радиус; начальный предлагаемый радиус — 5 км. Поиск применяется по кнопке «Найти».

Сохраняем два состояния: черновик фильтров и применённые параметры URL. Движение карты само по себе не отправляет API-запросы и не меняет центр поиска. Клик при включённом режиме выбора центра изменяет черновик, после чего пользователь нажимает «Найти».

## Координаты без путаницы

| Представление | Формат |
|---|---|
| Наш HTTP API | `{longitude: 71.4304, latitude: 51.1282}` |
| Leaflet | `[latitude, longitude]` → `[51.1282, 71.4304]` |
| MongoDB GeoJSON | `[longitude, latitude]` — это преобразование делает backend |

В `shared/lib/coordinates.ts` две именованные функции преобразования API ↔ Leaflet. По коду не разбрасываем неименованные пары чисел. Нулевые координаты валидны. Не округляем значения перед запросом; округление применяется к подписи на экране.

Границы: latitude −90…90, longitude −180…180. Радиус в UI можно вводить в километрах; перед отправкой переводим в целые метры и проверяем 1…50000. Пустое поле не преобразуется в 0.

## Правила фильтров

Пример URL страницы:

```text
/explore?q=postman&category=cafe&tag=quiet&tag=wifi&longitude=71.4304&latitude=51.1282&radius_m=1000&limit=20&offset=0
```

Пример API-запроса с теми же бизнес-параметрами:

```text
/api/v1/places?q=postman&category=cafe&tag=quiet&tag=wifi&longitude=71.4304&latitude=51.1282&radius_m=1000&limit=20&offset=0
```

- `q` — начало всего названия, не произвольное слово из середины. В UI это поясняем. Демо-названия часто начинаются с «Астана», поэтому для них полезнее категории/теги/радиус.
- Категория одна; теги повторяются через `URLSearchParams.append('tag', value)`, не через запятую. Все фильтры объединяются AND.
- Пустые `q/category` не отправляем. Отключённый геопоиск убирает все три geo-параметра.
- Все три geo-параметра либо заданы вместе, либо отсутствуют. Частично заполненную группу не отправляем.
- Новые фильтры сбрасывают offset на 0. Переход по страницам сохраняет фильтры.
- Некорректный URL разбираем и показываем ошибку фильтров до запроса; не выдаём молча другой запрос за выбранный пользователем.
- Нельзя передавать несуществующий `sort`, bbox, несколько категорий или фильтры даты. Обычная сортировка задаётся сервером по названию, геопоиск — по расстоянию.

## Порции и маркеры

На карте отображается ровно текущая порция списка. Подпись: «На карте показаны места с этой страницы». Не называем её полным набором заведений в радиусе, не догружаем все страницы скрытно. Маркер выбирает карточку в списке; «Подробнее» открывает отдельную страницу.

Круг поиска отображает применённый центр и радиус. Его граница не является административной границей города. Расстояние из API — по сфере, не маршрут пешком или на автомобиле. При `distance_m=null` расстояние не показываем и не заменяем нулём.

Ответ содержит `has_more`, но не total: «Далее» доступно, если `has_more=true` и следующий offset не превышает 10000. При достижении предела предлагаем сузить поиск. Одновременно отображаем до 100 мест — предел API; стартовый размер страницы 20.

Leaflet подключаем лениво при открытии карты. Контейнер имеет явную высоту; после переключения мобильной панели обновляем размеры карты. Изменение центра выполняем через небольшой map-controller, поскольку не все props React Leaflet меняются после создания карты. [React Leaflet: Introduction](https://react-leaflet.js.org/docs/start-introduction/).

## «Моё местоположение»

Запрашиваем один раз через браузер только по нажатию кнопки. Геолокация требует разрешения и безопасного контекста; локальную разработку проверяем на localhost, публикацию — на HTTPS. [MDN: Geolocation API](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation_API).

При отказе, таймауте или отсутствии поддержки остаются выбор точки на карте, числовые поля и кнопка «Центр Астаны». Отказ не повторяет запрос разрешения по кругу. Непрерывное слежение не нужно. Перед отправкой поиска показываем выбранную точку; не записываем её в профиль или localStorage.

Применённые координаты входят в URL фильтров, поэтому переданная другому человеку ссылка раскрывает центр поиска. Это должно быть понятно по видимым параметрам; отдельную функцию публичного шаринга геопозиции не добавляем.

## Подложка карты

Для локального учебного стенда планируем стандартные raster tiles OpenStreetMap: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, с видимой атрибуцией `© OpenStreetMap contributors` и ссылкой на источник. Сохраняем браузерное кэширование и Referer; не делаем массовую предзагрузку, offline-кэш всей области или обход ограничений. Сервис имеет best-effort доступность, не гарантирует SLA. [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).

URL и атрибуция провайдера — публичные build-настройки (`VITE_MAP_TILE_URL`, `VITE_MAP_ATTRIBUTION`). В переменные `VITE_*` нельзя класть секреты: они попадают в браузерный bundle. Перед публичным запуском отдельно выбираем провайдера с подходящими лимитами. API мест от провайдера подложки не зависит.

При недоступных тайлах показываем сообщение, список и числовой выбор центра продолжают работать. Запросы изображений карты идут непосредственно к провайдеру и раскрывают ему просматриваемую область/IP; cookie GeoAssist и заголовки нашего API туда не передаём.

Геокодирование адреса и построение маршрута в этот этап не входят. Мы не вызываем сторонний поиск адресов при каждом вводе символа.
